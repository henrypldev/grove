Grove stores its configuration in `~/.config/grove/`.

## Files

| File | Description |
|------|-------------|
| `cli.json` | CLI configuration (port, etc.) |
| `grove.db` | SQLite database (repos, teams, agents, activity) |
| `certs/` | Tailscale TLS certificates for ttyd |
| `pid` | PID file for the background server process |

## CLI Configuration

The CLI configuration file at `~/.config/grove/cli.json` stores persistent settings.

```json
{
  "port": 3001
}
```

### Options

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `port` | `number` | `3001` | Server port |

The port can also be set per-invocation with the `--port` flag, which takes precedence and updates the saved config.

## Repository Configuration

Repositories are managed through the API or mobile app and stored in the database. Each repository tracks:

- **Path** — Local filesystem path
- **Name** — Display name
- **Framework** — Auto-detected framework (Expo, Next.js, etc.)
- **Environment variables** — Key-value pairs written to `.env` files in worktrees
- **Setup steps** — Commands that run when a team worktree is created
- **Scripts** — Custom commands that can be run against teams

### Environment Variables

Environment variables are defined per repository and written to worktrees when teams are created:

```json
{
  "key": "DATABASE_URL",
  "value": "postgresql://localhost:5432/mydb",
  "filePath": ".env.local"
}
```

| Field | Required | Description |
|-------|----------|-------------|
| `key` | Yes | The environment variable name |
| `value` | Yes | The environment variable value |
| `filePath` | Yes | Path where the env file will be saved (relative to repo root) |

### Setup Steps

Setup steps run automatically when a team worktree is created. You can also place a `.grove/setup.json` file in your repository:

```json
{
  "setup": [
    {
      "name": "Install dependencies",
      "run": "bun install"
    },
    {
      "name": "Build project",
      "run": "bun run build"
    }
  ]
}
```

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Display name shown in the UI |
| `run` | `string` | Shell command to execute |
| `background` | `boolean` | If `true`, the step starts but doesn't block — the next step begins immediately |

#### Behavior

- Steps run sequentially in the worktree directory
- Each step streams output in real-time to the UI
- If a step fails, subsequent steps are skipped
- You can cancel, retry, stop, or restart individual steps
- Background steps are useful for long-running processes like dev servers

#### Auto-detection

Grove can auto-detect setup steps for your project. Trigger detection via the API or mobile app, and Grove will analyze your repository to suggest appropriate setup commands.

### Scripts

Scripts are custom commands defined per repository that can be run against any team. They're useful for common operations like running tests, linting, or deploying.

```json
{
  "name": "Run tests",
  "run": "bun test",
  "background": false
}
```

## Server Settings

Server settings can be configured via the API:

```typescript
// Get all settings
const settings = await client.config.settings.get()

// Update settings
await client.config.settings.update({
  settings: { key: 'value' }
})
```

## Clone Directory

Configure where GitHub repositories are cloned to:

```typescript
// Get current clone directory
const { cloneDirectory } = await client.config.cloneDir.get()

// Set clone directory
await client.config.cloneDir.set({ cloneDirectory: '/Users/you/Projects' })
```

## TLS Certificates

Grove uses Tailscale certificates for HTTPS terminal access. Certificates are generated automatically using `tailscale cert` and stored in `~/.config/grove/certs/`. They are reused across sessions for the same Tailscale hostname.
